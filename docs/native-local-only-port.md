# Default-off local-only native settings port

This source candidate adds an explicit `RISC_NATIVE_SETTINGS_LOCAL_ONLY=1` policy. The default remains ExternalVolume. LocalOnly requires volume instance zero and consistent Core, store and checked fresh/import collector policies. It never constructs an external synchronization client or acquires an external volume. `RISC_NATIVE_SETTINGS_LOCAL_FRESH` separately authorizes checked empty genesis and defaults to zero; interrupted exact local receipts can resume without that permission.

Existing external V1–V4 roots and old initialization receipts are refused under the worker-owned fence before writer availability or data mutation. No migration, external acknowledgment or release of an existing replica obligation is inferred. Imported local V5 images retain their archive obligation. NativeInitializeResult collects successful initialization even when cancellation arrives after its worker committed. The internal Synchronized result denotes completed source initialization, not an external acknowledgment.

The local port fixture compiles the real Backend, Assembly, both Worker tasks, Bootstrap, Maintenance, Lifecycle, Runtime and fenced LittleFS path. It uses host NVS/RTOS/heap shims and an empty board/package graph with no volume driver or installation envelope; native LocalOnly selects device zero. The two workers must each request 8192 bytes. Function-entry instrumentation rejects NativeSdPortAttempt::acquire; an isolated deliberately forbidden call must be intercepted with exit86. Cancellation boundaries are observed through actual queueNative and initializeNative entries, not loop counts.

Initial cases cover fresh permission on/off, opaque legacy namespace6 import preserving namespace1 and peer files, cancellation before inspection, after initialization queue but before its worker, cancellation after worker success before collection, an accepted atomic edit and process reboot/readback, held data/atomic grant reconciliation, and exact external fresh/import/unclassified or malformed metadata refusal. Worker-observed instrumentation counters are atomic; condition-variable worker tickets still provide the parked observation boundary. Normal and ASan/UBSan jobs retain LeakSanitizer. These cases are not yet the complete product qualification: full native power-cut campaigns and target retained recovery remain required, in addition to existing Core and checked-store crash-cut suites.

No product profile enables this policy. Existing external host campaigns stay separate. Neither host heap measurements nor the namespace mask prove firmware admission or reduce the two-worker budget. A later combined Runtime pin needs independent target link, INTERNAL/PSRAM/stack and real shared AppData capacity evidence. Existing native firmware and external fixture pins remain unchanged.

Additional isolated host cases cut after the actual NVS shim commits RTENFL1/RTENLL1, persist full LittleFS bytes plus NVS state, and resume through the real worker/bootstrap path. Fresh=0 jobs obtain a genuine receipt from a separately compiled Fresh=1 producer, then resume with every consumer compilation unit still Fresh=0. The retained initialization case injects the existing real-flash program fault, requires unavailable retained custody and unchanged subsequent I/O counters, and terminates its isolated process without destroying retained controls. Ordinary cases retain normal teardown and LeakSanitizer. The host mount bridge only separates incompatible glibc/newlib DIR types; it forwards every operation to the unchanged production mount and does not manufacture custody.

Two additional proof boundaries are explicit in the fixture. The atomic case waits for the instrumented real NativeAtomicKeyValue::workerStep return and a new Core revision while both worker tickets are parked, then requires unavailable exit custody and BUSY state/second submission until the original terminal receipt is collected. Per-case intent IDs avoid confusing reboot idempotency with a new commit. A separately compiled ExternalVolume producer creates a genuine V3 imported root and immutable bank through the unchanged checked native import fallback; its missing external provider permits no media writes. The LocalOnly consumer loads that exact full flash/NVS snapshot and must refuse it before availability or mutation. Only the explicitly external producer may enter acquire; every LocalOnly case retains the fatal acquire hook and isolated negative control. These additions require their own CI results and do not imply target qualification.

Target DWARF from the rejected combined X4 link identified collector policy-field padding as the Backend state growth. The collectors now use a one-byte checked selection beside existing boolean fields. The public policy remains uint32_t and all persisted encodings are unchanged. Full-width validation precedes encoding; every unsupported input becomes an invalid sentinel and inventory/materialization refuses before NVS I/O or allocation. Tests cover all low16-bit values, upper-bit aliases and both valid policies. This representation candidate must pass fresh native link/resource qualification; no limit, bank, placement or worker budget is changed.
