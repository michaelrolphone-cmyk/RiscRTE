# Hardware one-bit SDMMC host

The optional `RISC_ENABLE_SDMMC=1` native feature replaces per-bit GPIO callbacks with ESP-IDF hardware SDMMC transfers. It publishes the tagged `RiscGpioSdmmcV1.h` suffix on a selected `gpio.bank`. The original `garden_gpio_v1` layout is unchanged; a runtime without the feature continues to provide the old table. The filesystem, card power sequence, sleep recovery and USB export remain in the ELF storage provider.

The host uses one-bit mode at a conservative 20 MHz maximum, board-selected CLK/CMD/DAT0, no extra chip-select, and an exclusive controller session. Its permanent 4096-byte internal DMA buffer handles unaligned or PSRAM caller buffers by copying; no caller/ELF buffer remains borrowed after return. A failed transaction cannot be retried as an uncertain write. Teardown must stop the controller before pin ownership can retire. Incomplete SDK initialization without a safely deinitializable host is retained rather than touching an unrelated controller or freeing live DMA memory.

`test/run_sdmmc_port_test.sh` exercises the actual CPU port: selected-bank and pin conflict handling, old-table rejection, full tokens and owner checks, bounds, unaligned byte copies, read/write/sync failure, failed initialization and retriable teardown. `test/run_native_sdmmc_test.sh` compiles the actual native implementation against a narrow SDK-call model to verify one-bit/20 MHz configuration, exact pins, permanent DMA-buffer use, unchanged caller output on failed reads, and cleanup failures. Both run normally and with ASan/UBSan. The target environment `esp32s3-16mb-appdata-iq-stage-sdmmc` compiles the real ESP-IDF implementation and retains the `risc_sdmmc_host_abi=1` marker.

This feature is developed on the existing `perf/scoped-gpio-read-0188` working branch. It preserves that branch's GPIO-read lookup optimization. It is not a replacement for the separately composed Runtime .96 resident-loader work: forward-port this additive feature onto that source before assembling a new current X4 image. Do not downgrade an X4 product pin to this older ancestry. The X4 composition option `--sdmmc` requires the feature source and checks the linked native marker.

Host tests establish software behavior, not electrical timing or device throughput. Validate card mounting, ROM load timing, save-state loading, repeated sleep/wake, USB export/return and card-removal handling on the X4 hardware before describing it as hardware-qualified. Existing save formats and filesystem bytes are not migrated.
