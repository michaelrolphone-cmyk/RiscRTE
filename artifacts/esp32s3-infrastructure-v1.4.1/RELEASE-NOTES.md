Fixes the v1.4.0 regression that prevented RiscRTE-Setup Wi-Fi and the captive portal from starting.

The device boot log showed state_missing_corrupt_or_schema. The journal passed a 96 KiB read capacity to the runtime, whose file API permits 64 KiB. This rejected even the small valid setup seed. v1.4.1 binds the journal capacity and JSON lexical gate to the SDK file limit, and reports the correct capacity in inventory. No storage format or native runtime ABI change is required. The portal, encrypted message-bus webhook enrollment, and Scheduler timeout correction remain included.

Validation: the new test links the production filesystem backend, reproduces the old startup failure, and passes the fix, >60 KB save/reload/reboot, and rejection of oversized writes without changing committed data. ASan/UBSan tests pass captive redirects, setup/save/recovery, three exact pairing cohorts, encrypted enrollment, rotation/revocation, relay retry/reboot/dead-letter behavior, and the 173-call maintenance regression (28 wakes, four reboots). Target compilation and complete image/component/source/paired-bank/ELF verification pass. Physical v1.4.1 access-point/portal and real Grok delivery qualification remain pending.
